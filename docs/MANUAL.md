## 1. 追更

首页展示本季新番的播出日历，按周一到周日分组。数据来自 Bangumi 的放送时间表，只保留日本制作的条目（用 Bangumi 的 `meta_tags` 判断产地，过滤掉韩国美国动画/国漫等）。

日历数据会在本地缓存（浏览器 `localStorage`），1 小时内重复打开不会重新请求。如果发现数据明显过期（比如新番表更新了但页面没变化），可以强制刷新页面清空缓存重新拉取。

点开某一部番会进入详情页。

## 2. 搜索 / 详情

**搜索页**支持按关键词 + 年份 + 季度筛选检索 Bangumi 番剧库，结果分页加载（"加载更多"）。搜索状态（关键词、筛选条件、已加载的结果）会话内保留——从详情页返回搜索页时不会丢失之前的搜索结果。

**详情页**展示封面、标题、放送日期、话数等信息，同时嵌入一个 WebView 直接加载 bgm.tv 页面获取更完整的介绍（有 12 秒加载超时）。详情页本身是只读的，不会往数据库写东西——真正"加入库/开始追"是在下载页或 RSS 订阅完成后自然发生的。

详情页有两个按钮跳转到下载页（单次下载）或直接创建 RSS 订阅（长期追更）。

## 3. 下载

下载页做的事情：**关键词命中资源 → 筛选 → 改名预览 → 提交给 qBittorrent**。

- **数据源**：dmhy / AnimeGarden / nyaa.si 三选一，不提供"全部一起搜"——保证这里搜出来的结果和 RSS 订阅将来会匹配到的范围是一致的，不会出现"下载页能搜到但订阅永远匹配不到"的落差。
- **筛选项**：画质（1080p/720p/2160p/不限）、字幕语言、文件格式、单集/合集。画质和格式会真的拼进站点的搜索关键词里发给服务端（缩小搜索范围到全站历史，而不是只看第一页）；字幕语言完全在前端本地过滤（因为单个 CJK 字符当搜索词很多站点搜不出东西，拼进去反而会把结果冲空）。
- **改名预览**：提交下载前会先展示这个资源解析出来的目标文件名/归档路径，确认没解析错再点确认。
- **两种提交方式**：直接下载这一个资源，或者"改成建 RSS 订阅"——如果这部番还有后续没出的集数，建订阅比手动下载更省心。

> dmhy 对搜索有防刷限制，短时间内翻页太多次可能会被限流一段时间（症状：搜索结果为空但站点本身能正常打开）。遇到这种情况换 AnimeGarden 或稍等一段时间即可，本工具本身没有重试或绕过限流的机制。

## 4. RSS 订阅

RSS 订阅一览页管理"长期追更"的规则。这里的轮询引擎是**完全自建的**：后台按设置里配置的间隔（1–1440 分钟）轮询每条启用中的订阅，抓 RSS/Feed，逐条判重，命中关键词/字幕组/画质条件的直接拿磁力链接提交下载。

每条订阅可以看到：
- 启用/禁用开关（只影响要不要参与轮询，禁用不会删除历史记录）
- 匹配到的条目列表，每条标注下载状态（已下载/失败/已跳过）
- **上次轮询时间**：不管这次轮询有没有抓到新东西，只要真的发起过一次尝试就会更新这个时间戳，用来判断"这条订阅是不是还活着"，和"上次成功命中的时间"是两个概念
- 删除订阅前会有二次确认，防止手滑

轮询间隔在**设置页**统一配置，不是每条订阅单独设置。

## 5. 下载详情

展示 qBittorrent 里 `anime-hub` 分类下的任务实时状态：进度百分比、速度、大小、状态（下载中/已完成/已整理/出错），每 5 秒自动刷新一次。"已整理"表示文件已经被自动改名归档进媒体库了；如果长时间卡在"已完成"没有变成"已整理"，通常是改名规则解析失败或目标目录写入权限有问题，去看后端日志（`service.log`）能定位到具体原因。

支持批量选中删除任务。

## 6. 本地媒体库

展示已入库番剧的封面/标题/简介网格，可以按默认顺序/最近观看/最近更新排序。点进一部番能看到分季度的分集列表，看过的集数会有标记。

**播放方式**有两种：
- 内置 mpv 连续播放——放完自动接播下一集，支持断点续播（`--save-position-on-quit`）
- 外部播放器（比如 PotPlayer）——在设置页配置外部播放器路径后，点播放会呼出外部播放器；因为 PotPlayer 没有提供进度回调接口，HamStash 是通过监视 PotPlayer 窗口标题（格式固定是"文件名 - PotPlayer"）来判断你看到了哪一集，从而同步观看进度的。如果发现进度没同步，检查一下播放器窗口标题有没有被自定义皮肤/语言设置改掉格式。

如果某个文件夹的名字和 Bangumi 词条对不上（比如用了非官方译名），可以在库里手动搜索绑定正确的条目，这个操作只改数据库里的匹配关系，不会碰物理文件夹本身。

也支持从库里直接删除某部番（连同本地文件，操作前会二次确认）以及打开文件所在文件夹。

## 7. 设置与首次引导

**首次启动**会自动检测本机 qBittorrent 状态，分三种情况引导：
1. 已安装且 WebUI 已开启 → 直接测试连接
2. 已安装但 WebUI 没开 → 提示去 qBittorrent 设置里开启 WebUI
3. 没检测到安装 → 提示先安装 qBittorrent

检测到能连上之后，可以一键应用"推荐配置"：开启 RSS 处理、关闭 Host Header 校验（避免本地访问被拒）、放宽防爆破锁定阈值（避免连接测试触发锁定）。

**设置页**里能改的东西：
- 下载暂存目录 / 媒体库目录路径
- RSS 轮询间隔（1–1440 分钟）
- qBittorrent 连接信息与连接测试
- 代理连通性诊断（手动配置的代理优先，没配就退回系统代理，系统代理探测结果缓存 60 秒）
- 主题（浅色/深色）
- **数据库导出/导入**：换机器前先在旧机器导出一份，装到新机器上导入即可恢复观看记录、订阅规则等全部数据

## 8. 常见问题 FAQ

**Q: dmhy 搜索突然一直没结果，站点本身能打开？**
大概率是被 dmhy 的防刷机制限流了。换 AnimeGarden 或 nyaa.si 试试，或者过一段时间再用 dmhy。目前没有已知的固定解封时长，也没有自动重试机制。

**Q: 设置页测试 qBittorrent 连接一直失败？**
先确认 qBittorrent 客户端本身在运行，且 WebUI 已经在"选项 → Web 用户界面"里打开；再确认 HamStash 设置里填的地址/端口/账号密码和 WebUI 一致。如果 WebUI 开了 Host Header 校验，浏览器本地访问也会被拒——首次引导页的"应用推荐配置"能一键关掉这个校验。

**Q: 换新电脑了，怎么迁移数据？**
在旧机器的设置页导出数据库备份文件，装好新机器上的 HamStash 后在设置页导入即可。另外，只要媒体库所在的磁盘本身被完整迁移过去（比如换主机但保留了原来的媒体库硬盘/NAS 挂载），数据库文件本来就随媒体库目录走（存成媒体库目录下的隐藏文件 `.anime_hub.db`），不需要额外导出导入。

**Q: Windows 服务用什么账号跑？媒体库在网络共享盘上访问不了怎么办？**
默认用 `LocalSystem` 账号注册服务，但 `LocalSystem` 没有网络身份，访问不了需要账号密码认证的网络共享盘。如果你的媒体库目录在局域网共享盘上，需要把服务改成用一个有权限访问该共享的 Windows 账号运行（这属于机器本地的运维配置，不随版本库同步）。

**Q: 卸载后重装，数据会不会丢？**
不会。卸载程序只停止/移除 Windows 服务本身，不会删除 `%ProgramData%\hamstash\` 或媒体库目录下的数据库文件。
